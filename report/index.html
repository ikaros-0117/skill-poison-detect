Skill 投毒安全检测服务

面向 AI Agent Skill 的投毒 / 恶意行为安全检测后端。对上传的 Skill 包（zip）执行静态规则 + 可选 LLM 语义分析，输出风险评分、发现项与 SARIF 报告，并支撑流水线门禁。

检测引擎：SkillSpector 2.9.6（Apache-2.0） 控制面：Spring Boot 2.7.18 / Java 8 / MyBatis-Plus 检测规则：17 类 / 72 条 部署：Docker Compose 单机

1项目概览

一句话定位：为“AI Agent Skill 安装前”提供自动化安全检测能力，识别提示注入、数据外泄、供应链投毒、恶意代码执行等风险。

🎯 目标

在 Skill 被安装/运行前发现投毒与恶意模式，给出可解释的风险结论与修复建议。

🧩 组成

Spring Boot 控制面 + FastAPI 引擎薄封装 + SkillSpector 检测核心。

🔌 交付

HMI 交互接口、M2M 流水线接口（异步 + 轮询 + SARIF）、健康/监控接口。

能力清单

  • 静态扫描：17 大类 72 条规则，覆盖 Prompt Injection、Anti-Refusal、Data Exfiltration、Privilege Escalation、Supply Chain、YARA 恶意样本、MCP 权限/工具投毒等。
  • 语义分析（可选）：接入内部 OpenAI 兼容网关，做行为/意图语义判定，输出静态 + LLM 双模式结论。
  • 异步任务与门禁：Redis 队列 + MySQL 事实来源，支持并发、取消、重试、可配置风险阈值门禁（pass/fail）。
  • 报告输出：JSON / Markdown / SARIF 2.1.0，可直接对接 CI 流水线。
  • 工程化保障：限流、引擎熔断、启动对账自愈、30 天留存清理、Prometheus 指标、健康探测。

5.3 LLM 语义分析

启用 useLlm=true 时，引擎将 3 个语义分析器（开发者意图、安全发现、质量策略）+ 按文件分批的 meta_analyzer 接入内部 OpenAI 兼容网关，并将静态与语义结论融合输出。报告会诚实呈现 llm_requested / llm_available / llm_used 三态，避免“声称用了 LLM 但实际未执行”的歧义。

本地已把 SkillSpector 工作流预算从 60s 调至 600s（对应 Server 引擎调用超时 720s），保证 LLM 多文件扫描有充足时间；该改动已提交。

7可靠性 / 可观测 / 安全

🛡 可靠性

  • 事实来源：MySQL 权威，Redis 可重建，重启对账补队列不丢任务。
  • 自愈：启动/周期把“QUEUED 但不在队列”的任务补入队；超时 RUNNING 置 FAILED(TIMEOUT)。
  • 熔断：引擎连续失败达阈值即开路，半开探活恢复。
  • 取消/重试：排队中直接 LREM；运行中结果被守卫忽略；网络类错误按 retry_count<3 重投。

📈 可观测

  • /healthz、/readyz、/api/v1/engine/health（含 deep 探活）。
  • /actuator/prometheus 暴露 skillscan_queue_depth 等指标。
  • 引擎健康历史写入 engine_health_log。

🔐 安全（预留）

  • HMI：OIDC/SSO（JWT），身份写入 created_by。
  • M2M：X-API-Key，密钥仅存哈希，支持 scope/过期。
  • 引擎内部：可选 X-Engine-Token，仅内网监听。
  • 当前 security.enabled=false，接口与数据模型已预留，可开关化启用。

🚦 限流

  • Redis 固定窗口按 IP 区分 HMI（120/min）与 M2M（60/min）。
  • 上传限制 100MiB，落盘后 sha256 校验。
  • 引擎侧 ENGINE_MAX_CONCURRENT_SCANS=8 作为第二道保护。
